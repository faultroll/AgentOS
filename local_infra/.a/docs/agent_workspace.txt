# Build `.a` — A Reproducible Open Agent Runtime for VSCodium

You are helping design and bootstrap a portable, reproducible, open-source AI coding runtime for VSCodium.

This is NOT a “chatbot IDE”.

The goal is:

```text id="b7xv8x"
Composable Agent Runtime
+
Artifact-driven workflows
+
Stateless workers
+
Strong sandboxing
+
Provider abstraction
```

The system should be repository-centric and reproducible.

---

# PRIMARY GOALS

Build a `.a/` repository that can be cloned into any software project.

The repository should provide:

* AI coding workflow
* multi-role agent orchestration
* provider abstraction
* transparent prompts
* sandboxed execution
* reproducible IDE configuration
* disposable workers
* persistent planner memory

The final system should work primarily inside:

* VSCodium
* VSCode-compatible environments

Target platform:

* Windows (primary)
* Linux/macOS compatible where possible

---

# REQUIRED ARCHITECTURE

The system MUST separate:

```text id="c9i91m"
Planner
≠
Worker
≠
Reviewer
```

DO NOT implement a giant monolithic persistent chat.

Instead implement:

```text id="mjlwmx"
Planner
→ generates plan artifacts

Worker
→ executes isolated tasks

Reviewer
→ validates outputs
```

Workers MUST be disposable and stateless.

---

# REQUIRED BEHAVIOR

## Planner

Planner should:

* reason
* decompose
* generate plans
* maintain architecture memory

Planner should NOT:

* directly edit code
* execute shell commands

Planner output:

```markdown id="6jlwmxy"
PLAN-XXX.md
```

---

## Worker

Worker should:

* consume task artifacts
* modify ONLY allowed files
* generate walkthroughs
* produce result artifacts

Worker MUST be stateless.

Worker lifecycle:

```text id="7jlwmxy"
spawn
→ execute
→ summarize
→ destroy context
```

Worker output:

```markdown id="8jlwmxy"
RESULT-XXX.md
```

---

## Reviewer

Reviewer should:

* validate diffs
* detect regressions
* ensure style consistency

## 1. Artifact-centric, NOT chat-centric

## 2. Stateless workers

## 4. Modular architecture

Everything replaceable:

* providers
* prompts
* orchestrators
* sandboxes
